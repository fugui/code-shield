# 无序集合导出缺陷代码检视综合报告生成指令

你将收到一份 JSON 格式的无序集合顺序依赖与导出风险评估数据（基于 @analysis_prompt.md 提示词进行的分析）。请基于这些发现，生成一份指导开发者进行修复与确定性治理的综合评估报告。

## 输入说明

输入为 JSON 格式的评估数据对象（Schema: `code-shield.tier4-synthesis-input.v1`），包含以下关键部分：
- `report`: 代码仓与检视基本元信息（`repo_name`, `task_type`, `head_commit` 等）
- `statistics`: 各严重级别缺陷统计数据（`fatal`, `critical`, `minor`, `suggestion` 等）
- `detailed_findings`: 重点无序集合导出缺陷详细列表，每个元素包含 `severity`, `category`, `file_path`, `line_number`, `code_snippet`, `title`, `detail`, `suggestion`
- `summary_findings`: 其余缺陷简要索引列表（包含 `file_path`, `line_number`, `title`, `severity`）

## 输出格式要求

请使用简体中文，以 Markdown 格式输出，内容包括"一、检视结果概要"、"二、无序集合导出风险清单"、"三、总结与预防建议"三部分。

### 一、检视结果概要
- 检视目的和无序集合下游确定性影响评估方法的简要介绍。
- 总结潜在无序集合遍历与导出风险分布情况（致命、严重、一般、建议）。

> ⚠️ **概要部分的最后一行，格式约束（机器解析硬性约束，不得违反）**：
> - 必须严格使用 `致命：N，严重：N，一般：N，建议：N` 的格式，关键字和标点均不得更改
> - 冒号使用中文冒号 `：`，分隔符使用中文逗号 `，`
> - N 为非负整数，无问题填 `0`

### 二、无序集合导出风险清单
- 按照严重程度从高到低（致命 -> 严重 -> 一般 -> 建议）对风险列表进行整理排版。
- 每一个隐患条目应展示清晰的文件位置（包含代码行号）、风险分类、严重级别。
- 提供原汁原味的代码片段并突出显示风险行。
- 提供对应的下游顺序敏感性影响分析（如签名失效、跨端接口漂移、下标错位等），并给出具体的保序容器或显式排序修复方案。

### 三、总结与预防建议
- 评估本代码仓整体的集合迭代与跨模块数据流契约稳定性水平。
- 给出系统性的无序集合稳定性预防建议（例如：在安全签名与接口序列化前强制执行 Key 字典序排序、对插入顺序敏感场景选用保序容器如 LinkedHashMap、避免对两个独立导出的切片采用相同下标索引等）。
