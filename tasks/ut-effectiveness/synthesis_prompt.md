# 测试用例有效性评估 报告总结指令

你将收到一份 JSON 格式的用例有效性评估数据（基于 @analysis_prompt.md 提示词进行的分析）。请基于这些发现，生成一份面向研发团队与技术管理者的综合 Markdown 评估报告。

## 输入说明

输入为 JSON 格式的评估数据对象（Schema: `code-shield.tier4-synthesis-input.v1`），包含以下关键部分：
- `report`: 代码仓与检视基本元信息（`repo_name`, `task_type`, `head_commit` 等）
- `statistics`: 统计数据（包含各类严重度统计 `fatal`, `critical`, `minor`, `suggestion` 以及合格用例数 `pass`）
- `detailed_findings`: 详细单测缺陷列表，每个元素包含 `severity`, `category`, `file_path`, `line_number`, `code_snippet`, `title`, `detail`, `suggestion`
- `summary_findings`: 其余缺陷简要索引列表（包含 `file_path`, `line_number`, `title`, `severity`）

## 输出格式要求

请使用简体中文，以 Markdown 格式输出。报告需由"一、检视结果概要"、"二、问题清单"、"三、总结与建议"三部分组成：

### 一、检视结果概要
- 介绍审计的目标和评估策略，说明代码仓基本信息（代码仓名称、最新 Commit ID 等）；
- 概述测试用例整体质量，明确指出通过评估的合格测试用例数量（`statistics.pass`）；
- 统计有质量/有效性缺陷的测试用例分布情况。

> ⚠️ **概要部分的最后一行，格式约束（机器解析硬性约束，不得违反）**：
> - 必须严格使用 `致命：N，严重：N，一般：N，建议：N` 的格式，关键字和标点均不得更改
> - 冒号使用中文冒号 `：`，分隔符使用中文逗号 `，`
> - N 为非负整数，无问题填 `0`

### 二、问题清单
- **完整呈现要求**：必须完整呈现 `detailed_findings` 中的所有重点缺陷条目，严禁自行省略、合并或以“因篇幅原因略去”代替；
- **零缺陷安全退避**：若无缺陷（统计均为 0），本章节明确写明“本次评估未发现单测有效性缺陷，所有评估用例均符合质量规范”，无需列出条目；
- 按照严重程度从高到低（致命 -> 严重 -> 一般 -> 建议）对问题进行整理排版；
- 每个详细问题条目必须包含以下清晰结构：
  - **严重程度**：（致命 | 严重 | 一般 | 建议）
  - **测试方法**：从 `title` 或 `code_snippet` 中识别的用例方法名（若无独立方法名可使用标题）
  - **代码位置**：`file_path:line_number`（必须原样保留真实文件路径）
  - **缺陷类型**：问题所属分类（`category`）
  - **现状描述**：详细描述测试代码存在的具体缺陷，结合代码片段分析；
  - **改进建议**：给出具体的重构或修复方案，提供聚焦于核心断言与逻辑的精炼测试修复代码（避免过于冗长）。
- 若数据中存在 `summary_findings`，请在重点问题后以 Markdown 表格简要列出其余缺陷索引。

### 三、总结与建议
- 对该代码仓的整体测试有效性与防护质量进行评价。
- 提供针对性的工程化改进建议（如引入断言静态检查、拦截空测试与恒真作弊、规范 Mock 行为校验等）。
