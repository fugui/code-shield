# 显式创建线程报告生成指令

你将收到一份 JSON 格式的显式创建线程风险评估数据（基于 @analysis_prompt.md 提示词进行的分析）。请基于这些发现，生成一份指导开发者进行并发与生命周期管理的综合评估报告。

## 输入说明

输入为 JSON 格式的评估数据对象（Schema: `code-shield.tier4-synthesis-input.v1`），包含以下关键部分：
- `report`: 代码仓与检视基本元信息（`repo_name`, `task_type`, `head_commit` 等）
- `statistics`: 各严重级别缺陷统计数据（`fatal`, `critical`, `minor`, `suggestion` 等）
- `detailed_findings`: 重点多线程与生命周期缺陷详细列表，每个元素包含 `severity`, `category`, `file_path`, `line_number`, `code_snippet`, `title`, `detail`, `suggestion`
- `summary_findings`: 其余缺陷简要索引列表（包含 `file_path`, `line_number`, `title`, `severity`）

## 输出格式要求

请使用简体中文，以 Markdown 格式输出，内容包括"一、检视结果概要"、"二、显式创建线程清单"、"三、总结与改进建议"三部分。

### 一、检视结果概要
- 检视目的和多线程并发安全评估方法的简要介绍。
- 线程创建总体情况：可说明已确认合理的线程数量，以及存在并发安全/资源泄漏风险的线程数量。

> ⚠️ **概要部分的最后一行，格式约束（机器解析硬性约束，不得违反）**：
> - 必须严格使用 `致命：N，严重：N，一般：N，建议：N` 的格式，关键字和标点均不得更改
> - 冒号使用中文冒号 `：`，分隔符使用中文逗号 `，`
> - N 为非负整数，无问题填 `0`

### 二、显式创建线程清单
- 把线程创建的位置和分析结果列出来，按照严重程度从高到低（致命 -> 严重 -> 一般 -> 建议）对风险列表进行整理排版。
- 每一个隐患条目应展示清晰的文件位置（包含代码行号）、风险分类、严重级别。
- 提供原汁原味的代码片段并突出显示风险行。
- 提供对应的生命周期/数据竞争危害分析和具体可靠的多线程重构建议。

### 三、总结与改进建议
- 评估本代码仓整体的多线程与并发设计质量。
- 给出后续改进和规范多线程开发的指导建议（例如：引入统一线程池、避免裸线程分离 detach、使用 RAII 线程守卫托管生命周期等）。
