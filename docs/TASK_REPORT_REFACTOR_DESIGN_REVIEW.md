# Code-Shield 任务报告重构设计方案检视意见

> **检视对象**：`docs/TASK_REPORT_REFACTOR_DESIGN.md`（v1.1.0，Ready for Review）
> **检视日期**：2026-08-22
> **检视重点**：用户交互体验的合理性
> **检视方式**：设计文档逐节通读 + 对照当前前端/后端代码验证

---

## 0. 总体结论

设计文档的方向和痛点判断是准确的，值得按此推进；但交互设计上存在若干关键缺口，其中 2 个会直接影响“上线后用户是否觉得好用、敢用”：

1. **实体评估模式（Entity Assessment）下，整个“详细清单”视图的设计不成立**；
2. **“免登录团队分享”与现状矛盾，且未定义权限模型**。

建议在进入实施前优先补齐上述两项，并同步解决抽屉内容与加载策略的匹配、失败/空数据状态等问题。

---

## 1. 现状核对：痛点描述属实

文档第 1.2 节列出的痛点均已对照代码验证，并非虚构：

| 痛点 | 证据 |
| :--- | :--- |
| 抽屉缺少“详细清单”Tab | `ReportSidebar.tsx` 仅有两个 Tab：审计报告正文 / 运行轨迹与诊断 |
| 导出按钮意图与内容不对称 | “下载 JSON / 下载 Excel”实际请求 synthesis 接口，与“下载 MD”语义不一致 |
| 打印简陋 | 使用 `window.open` 拼 HTML 后 `print()`，无专用打印样式 |
| 严重级别映射重复维护 | `PublicReportFindings.tsx`、`AuditingWorkspace.tsx` 等各自维护一套 severity 色彩映射 |
| Handler 臃肿 | `handlers/task.go` 1037 行，包含 CRUD、MD 读取、CSV 拼接、通知触发 |
| 存储路径模糊匹配 | 多处 `filepath.Glob(report-%d-synthesis-*.json)` 兜底，文件命名缺乏规范 |

因此，导出菜单语义分组、三 Tab 归一、ReportViewer 组件族、存储协议化、三阶段迁移等方向均认同。

## 2. 必须修订的交互问题（P0）

### 2.1 实体评估模式下，Tab 2 设计不成立

文档 1.1 明确系统支持“缺陷攻关模式（Defect Tracking）”与“实体评估模式（Entity Assessment）”两种治理模式，但：

- 3.3 的清单卡片按“缺陷 + NPE 修复建议 + 缺陷生命周期”设计；
- 4.2 的 `TaskFindingItem` 字段（`suggestion`、`status: open/resolved/invalid`）均为缺陷语义；
- 5.4 的 Excel 列头同样按缺陷清单设计。

实体评估模式下没有“修复建议”，状态语义也不同（评估状态而非待处理/已解决），过滤维度可能不同。

**建议**：交互层面必须做 mode 感知：

- `governance_mode == 'entity_assessment'` 时，Tab 2 渲染为“实体评估清单”变体（标题、列头、状态选项、卡片操作随模式切换）；
- 或在设计文档中显式声明“本版先只支持 defect_tracking，实体模式保持现状并显式降级”。

否则实体模式用户打开后会看到语义完全错误的清单，体验比现状更差。

### 2.2 “免登录团队分享”与现状矛盾，权限模型缺失

文档 3.1 宣称全屏模式支持“免登录团队分享”，但实际情况：

- 前端 `/public/reports/:id` 路由被 `PrivateRoute` 包裹；
- 后端所有 report 接口均在鉴权 API 组内，无公开端点。

同时 Tab 2 卡片设计了“状态/责任人”下拉，若公共分享免登录，则这些控件必须隐藏（只读），或引入带身份与时效的分享令牌模型。

**建议**：设计文档必须明确二选一：

1. **真免登录**：增加分享 token（如 `/share/:token`，可过期，默认只读），公共分享页清单卡片只读，隐藏治理控件；
2. **仍登录**：路由与文案不要使用 `public`，避免链接语义误导。

## 3. 应该修订的交互问题（P1）

### 3.1 抽屉宽度与三 Tab 内容不匹配

当前抽屉宽度为 `min(960px, 92vw)`。文档中：

- Tab 2 是“筛选栏 + 卡片（代码块 + 状态/责任人/复制/源码 5 个控件）+ 修复建议”；
- Tab 3 是分片矩阵 + 日志查看器。

960px 下会非常局促。

**建议**明确：

- 抽屉模式默认停靠 Tab（建议默认“总结概览”）；
- 清单/诊断 Tab 在抽屉内使用紧凑布局；
- 切到清单/诊断时是否自动加宽抽屉或引导用户点击“⛶ 全屏”；
- “⛶ 全屏”是路由跳转（深链可回退）还是原地扩展。

### 3.2 aggregate 全量拉取与“快速检视”目标冲突

3.1 强调抽屉是“快速检视”，但 5.3 设计了“一站式全量聚合”接口。大仓 findings 可能上千条、诊断日志 MB 级，一次全量拉取会让抽屉打开明显变慢。

**建议**：

- 抽屉模式只预载 summary + meta + findings 前 N 条（如 50 条），切 Tab 时按需分页/截断拉取；
- 全屏模式才使用 aggregate；
- `useTaskReport` 缓存策略需写明：治理操作（改状态/指派）后如何失效和刷新，避免展示陈旧数据。

### 3.3 失败任务、空数据、单引擎任务的状态未设计

`TaskReportMeta.status` 含 `failed` / `pending`，但三个 Tab 全部按成功态绘制：

- 失败任务没有 summary.md 与 findings，最有价值的是诊断日志——应默认定位到诊断 Tab 并显示错误横幅；
- 0 缺陷需有“通过”空态；
- 单引擎任务无分片矩阵，需“无分片数据”空态；
- 日志超大需截断 + “下载完整日志”入口。

### 3.4 打印语义与导出菜单割裂

`[🖨️ 打印 / PDF]` 位于导出菜单之外，但打印内容随当前 Tab 变化，文档未说明。

**建议**：

- 明确“打印当前标签页”；
- 规定 `@media print` 下隐藏的控件（筛选栏、状态/责任人下拉、按钮、导出菜单）；
- 导出菜单内同步提供“打印 / PDF（当前视图）”，或补充说明文字，避免用户多入口寻找。

## 4. 建议补充的交互细节（P2）

### 4.1 严重级别体系收敛

接口枚举 `fatal/critical/major/minor/suggestion/pass` 与界面中文（致命/严重/一般/提示/建议/合格），以及库中现存混合值（致命/fatal/阻塞/blocking/高风险/high…）之间，未定义映射与迁移策略。

筛选 chip 计数、Excel 高亮、严重度图表均依赖统一映射，不收敛则重构后依旧混乱。

**建议**：在 `types/report.ts` 定义 canonical 集合 + 显示映射，后端兼容层负责归一历史数据。

### 4.2 “左右切换任务”缺少落地点

ReportViewer 是通用组件，但各宿主页（概览/历史报告/工作台/执行日志/扫描管理）列表结构不同。

**建议**：

- 定义 props（如 `items` / `onNavigate`）；
- 无列表时降级为单任务；
- 切换时提供 loading 态；
- 如实现 ←/→ 快捷键，需避免搜索框聚焦时误触发。

### 4.3 导出体验

- 同步 GET 生成 ZIP 在大包场景有等待、超时、重复点击问题，需规定按钮 loading / 禁用；包很大时考虑异步任务 + 轮询；
- 文件名建议带仓库名与日期（如 `code-bench_2026-08-22_findings.xlsx`）；
- 中文文件名注意 RFC 5987 编码。

### 4.4 分享链接深链

分享应支持定位到具体 Tab 甚至具体 finding（如 `#findings`、`#finding-123`），复制链接需有反馈。

### 4.5 复制与提示

现有代码使用 `alert` 且 `navigator.clipboard` 在 http 内网可能失败，应统一为带兜底的 copy hook + toast。

### 4.6 可访问性

- 图标按钮（⛶、✕）需 tooltip / aria-label；
- 抽屉需 Esc 关闭与焦点管理；
- 头部按钮在窄屏应收进“更多”，避免重蹈 5 按钮拥挤的覆辙。

### 4.7 其他

- header “95分/优”的优/良/差分段阈值未定义，建议与总结 Tab 评级口径统一；
- “操作路径缩短 60%”等收益数字缺乏依据，建议换成可验证指标（如“清单查看不再跳页”“导出最多两步完成”）。

## 5. 建议修订优先级

| 优先级 | 事项 |
| :--- | :--- |
| P0 | 实体评估模式的清单视图变体（或显式降级声明） |
| P0 | 公共分享的权限模型（token / 时效 / 只读治理控件） |
| P1 | 抽屉内容与加载策略匹配（按需拉取 + 缓存失效） |
| P1 | 失败任务 / 空数据 / 单引擎任务状态设计 |
| P1 | 打印语义（当前 Tab）与导出菜单整合 |
| P2 | 严重级别体系收敛、左右切换落地、导出反馈、深链分享、a11y 等细节 |
