## 🎯 重构核心目标与量化指标

### 1. 解决的核心问题与重构本质
随着 Code-Shield 平台快速演进，近期先后引入了多智能体三权分立对抗辩论引擎（`DebateEngine`）、LLM 算力池平滑加权调度（`ModelDispatcher`）、确定性物理指纹与增量状态机（`DiffEngine`）、Native LLM 直连驱动等多项重大特性。

**重构本质洞察（神似而形散）**：
*   **业务主线（神似）**：现网中 `task_runner.go:RunTaskSync` 已经天然跑在正确的流水线大调度主轴上（Git同步 $\to$ 门禁 $\to$ 引擎 $\to$ 指纹Diff $\to$ 治理Hook $\to$ 脚本后处理 $\to$ 交付），业务灵魂高度成熟；
*   **物理工程（形散）**：由于缺乏及时的模块化组织，**全部 46 个源码文件（16,421 行代码）直接平铺在单个 `package services` 根命名空间中**，引发了以下 5 大结构性痛点：
    1.  **扁平大单包反模式**：命名空间无边界隔离，所有私有结构与辅助函数在 46 个文件间全局无阻可见；
    2.  **`taskContext` 上帝对象束缚**：扫描引擎与流水线强耦合，私有上下文导致分析引擎无法拆分子包；
    3.  **职责越权与逻辑分叉**：断点续跑（`ResumeFailedChunks`）越权写在 `engine_chunked.go` 内部，破坏了引擎契约；
    4.  **代码复制雷同**：`source_enricher.go` 与 `reconciliation/anchor.go` 存在近 1:1 的雷同复制代码；
    5.  **调度层次混杂**：宏观业务流水线大调度器与微观底层 LLM 算力池调度器概念混杂，巨型文件过载。

### 2. 预期重构量化成效 (Target Metrics)

| 指标维度 | 重构前现状 | 目标重构后 | 改善幅度 / 收益 |
| :--- | :--- | :--- | :--- |
| **`services/` 根目录文件数** | **46 个文件** | **$\le 5$ 个文件** | 根目录文件减少 **90%**，仅保留统一门面与生命周期协调器 |
| **根目录代码行数** | **16,421 行** | **$\le 800$ 行** | 根目录代码量锐减 **95%**，逻辑全部下沉至领域子包 |
| **包内循环依赖与跨层访问** | 严重隐式依赖 | **0（强编译期隔离）** | 通过 Go 包隔离（Package Boundary）建立显式调用边界 |
| **雷同重复代码** | 2 处完全雷同实现 | **0（单一真实源 SSOT）** | 提取 `defects/anchor` 公共模块，彻底遵循零重复原则 |
| **外部引用破坏性** | — | **0 破坏性** | 顶层采用 Facade（门面模式）向前兼容，外部调用方无缝过渡 |
| **测试通过率** | 100% | **100% 保持通过** | 每一阶段测试与代码检视闭环，不产生任何功能回归 |

## 🗺️ 目标架构设计速览

重构后的服务层将完全遵循**高内聚、低耦合、领域自治**的原则，形成如下 **9 个领域子包（7 个新建领域子包 + 2 个既有成熟子包）** 与 1 个顶层门面：

*   **双层调度体系**：将职责正交区分为**第一层宏观业务大调度器（`runner`）**（管代码检出、门禁、引擎分发、增量指纹比对、交付）与**第二层微观物理算力池调度器（`dispatcher`）**（管 SWRR 加权、槽位租约、健康熔断）；
*   **契约解耦与纯计算引擎**：用只读、字段最小化的纯数据对象 `EngineContext` 彻底终结包私有上帝对象 `taskContext`，并将 `context.Context` 提升为 `TaskEngine.Run` 的首参，引擎严禁直接访问 DB，实现毫秒级纯内存单元测试与零成本插拔扩展。

```
code-shield/services/
├── invoker/             # 【CLI 适配器层】统一 AI CLI 驱动（native, claude, opencode, codex, agy, agent_sync）
├── dispatcher/          # 【算力池调度】LLM 节点权重（SWRR）、槽位租约、健康探活与动态熔断
├── engines/             # 【分析引擎集群】标准化 EngineContext、single、chunked、debate 以及 semantic_chunker
├── defects/             # 【指纹与增量比对】收敛 SourceAnchor（SSOT）、L1物理强指纹、跨任务增量状态机
├── governance/          # 【专项治理与后处理】Campaign 归并引擎、严重度确定性校准树、Taxonomy白名单、误报记忆
├── queue/               # 【任务调度队列】TaskQueue、WorkerPool 竞争拉取与优雅排空
├── reconciliation/      # 【对账与仲裁】（已有独立子包，重构后直接依赖 defects/anchor）
├── reports/             # 【多格式导出】（已有独立子包，Excel/Markdown/JSON 导出）
├── runner/              # 【核心流水线】标准化生命周期 Pipeline、Git同步、JSON清洗、断点续跑、结果通知
└── services.go          # 【兼容门面 Facade】向后兼容导出公共函数，调用方零改动
```
