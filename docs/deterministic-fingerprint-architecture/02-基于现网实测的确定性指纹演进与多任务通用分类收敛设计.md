### 2.1 关键反思：L1 强指纹究竟需不需要包含 Category？
在代码审查和架构研讨中，我们提出了最关键的哲学命题：
> **同一个代码仓、同一个任务类型下，在同一个文件、同一个函数作用域、同一行物理触发行（TriggerLine），物理世界中可能同时存在两个不同的独立 Bug 吗？**

**答案是：几乎不可能！**
* 在《f.md》的 Match 6 中，同一行 `const auto enumValue = field.enum_type()->value(val);`：
  * R1 归入 `CWE-476: NULL Pointer Dereference`；
  * R2 归入 `CWE-125: Out-of-bounds Read`。
* 在研发人员与审计系统看来，**这就是物理代码同一位置的同一次风险检出！**
* **将 `Category` 塞进 L1 强指纹哈希，是大模型稍微发散就导致指纹失效的罪魁祸首！**
* **演进决断**：**L1 强指纹必须彻底剔除 `Category`！** 物理代码行不变，身份就不变。Category 仅作为辅助业务属性用于看板展示、统计聚合与二级弱容错。

### 2.2 关键反思：为什么后端绝对不能手写业务分类枚举？
系统包含十几个专项任务（`coredump_risk`, `memory_leak`, `thread_create`, `float_comparison`, `deep_review`, `ut_quality` 等），未来还会接入更多。
* 如果在后端用 `strings.Contains` 穷举成千上万个同义词，违背开闭原则，极易出现遗漏；
* **正解是**：**分类的单一真实源（SSOT）必须位于任务配置（`meta.json`）中**，提示词动态拉取该配置强制约束大模型，后端仅提供通用、无业务属性的字符吸附清洗器。

### 4.3 服务端通用最近吸附清洗器 (`SanitizeCategory`)
服务端完全不包含任何硬编码分类词表，仅实现 20 行通用的最长子串吸附与默认值兜底：

```go
// SanitizeCategory 通用受控分类吸附器（零业务侵入，纯配置驱动）
func SanitizeCategory(rawCategory string, allowedCategories []string) string {
	raw := strings.TrimSpace(rawCategory)
	if len(allowedCategories) == 0 || raw == "" {
		return raw
	}

	// 1. 完全匹配或忽略大小写完全一致
	for _, allowed := range allowedCategories {
		if strings.EqualFold(raw, allowed) {
			return allowed
		}
	}

	// 2. 包含匹配 / 最长子串吸附
	// 应对大模型输出了 "CWE-476: 空指针解引用" 或 "内存管理问题-空指针解引用"
	bestMatch := ""
	for _, allowed := range allowedCategories {
		if strings.Contains(raw, allowed) || strings.Contains(allowed, raw) {
			if len(allowed) > len(bestMatch) {
				bestMatch = allowed
			}
		}
	}
	if bestMatch != "" {
		return bestMatch
	}

	// 3. 兜底策略：取该任务类型白名单的最后一项（约定为“其它xxx隐患”）
	return allowedCategories[len(allowedCategories)-1]
}
```

### 4.4 源码物理定位反查与空行号自愈器 (`LineNumberHealer`)
针对现网 R2 报告中多达 20 处 `line_number` 为空的严重瑕疵，服务端在将裁决转换为 Finding 时执行物理源码反查：

```go
// HealMissingLineNumber 从物理源码中基于 trigger_line 自动反查真实行号
func HealMissingLineNumber(codesPath string, filePath string, triggerLine string, currentLine string) string {
	if strings.TrimSpace(currentLine) != "" {
		return currentLine
	}
	if strings.TrimSpace(triggerLine) == "" {
		return "1"
	}

	fullPath := filepath.Join(codesPath, filePath)
	contentBytes, err := os.ReadFile(fullPath)
	if err != nil {
		return "1"
	}

	cleanTrigger := strings.ToLower(NormalizeTriggerLine(triggerLine))
	lines := strings.Split(string(contentBytes), "\n")

	// 1. 首选：去除空白后完全匹配
	for idx, line := range lines {
		if strings.ToLower(NormalizeTriggerLine(line)) == cleanTrigger {
			return fmt.Sprintf("%d", idx+1)
		}
	}

	// 2. 次选：子串包含匹配
	for idx, line := range lines {
		if strings.Contains(strings.ToLower(NormalizeTriggerLine(line)), cleanTrigger) {
			return fmt.Sprintf("%d", idx+1)
		}
	}

	return "1"
}
```

### 4.5 确定性指纹公式演进 2.0 (`fingerprint.go`)

#### 4.5.1 C++ 作用域符号规范化 (`NormalizeScopeSymbol`)
彻底消除 `LSTB_COMMON::` 等外层命名空间前缀引起的哈希抖动：

```go
// NormalizeScopeSymbol 递归提取核心 Class::Method，剥离外层命名空间与模板参数
func NormalizeScopeSymbol(scope string) string {
	trimmed := strings.TrimSpace(scope)
	if trimmed == "" {
		return ""
	}

	// 处理多方法合并 "FuncA / FuncB"，统一取首个核心方法
	if strings.Contains(trimmed, " / ") {
		parts := strings.Split(trimmed, " / ")
		trimmed = parts[0]
	}

	// 剥离模板特化参数如 <T>, <std::string>
	reTemplate := regexp.MustCompile(`<[^>]+>`)
	trimmed = reTemplate.ReplaceAllString(trimmed, "")

	// 规范化 lambda 表达式
	if strings.Contains(trimmed, "operator()") || strings.Contains(trimmed, "lambda") {
		idx := strings.Index(trimmed, "::")
		if idx != -1 {
			return trimmed[:idx] + "::<lambda>"
		}
		return "<lambda>"
	}

	// 取末尾两段（Class::Method 或 Method）
	segments := strings.Split(trimmed, "::")
	if len(segments) >= 2 {
		return segments[len(segments)-2] + "::" + segments[len(segments)-1]
	}
	return segments[0]
}
```

#### 4.5.2 核心指纹计算公式（彻底解耦 Category）
```go
// CalculateDefectFingerprint 计算物理确定性强指纹 (L1 强指纹)
// 公式: SHA256(RepoID + TaskTypeID + NormalizedPath + NormalizedScope + NormalizedTriggerLine)
func CalculateDefectFingerprint(repoID uint, taskTypeID uint, filePath string, triggerLine string, scopeSymbol string) string {
	normPath := strings.ToLower(filepath.ToSlash(strings.TrimSpace(filePath)))
	normTrigger := NormalizeTriggerLine(triggerLine)
	normScope := strings.ToLower(NormalizeScopeSymbol(scopeSymbol))

	if normScope == "" {
		normScope = filepath.Base(normPath)
	}

	// 坚决剔除 Category！保证物理行不变指纹恒定
	rawKey := fmt.Sprintf("repo:%d|task:%d|path:%s|scope:%s|trigger:%s",
		repoID, taskTypeID, normPath, normScope, normTrigger)

	hash := sha256.Sum256([]byte(rawKey))
	return hex.EncodeToString(hash[:])
}

// CalculateWeakScopeFingerprint 计算作用域语义弱指纹 (L2 弱指纹)
// 用于当触发行被轻微重构或多行漂移时，在同一函数作用域内对齐同类缺陷
func CalculateWeakScopeFingerprint(repoID uint, taskTypeID uint, filePath string, scopeSymbol string, category string) string {
	normPath := strings.ToLower(filepath.ToSlash(strings.TrimSpace(filePath)))
	normScope := strings.ToLower(NormalizeScopeSymbol(scopeSymbol))
	normCat := strings.ToLower(strings.TrimSpace(category))

	rawKey := fmt.Sprintf("repo:%d|task:%d|path:%s|scope:%s|cat:%s",
		repoID, taskTypeID, normPath, normScope, normCat)

	hash := sha256.Sum256([]byte(rawKey))
	return hex.EncodeToString(hash[:])
}
```

### 4.7 分片与流转稳定性治理（消除 35% 文件覆盖抖动）

在 [semantic_chunker.go](file:///home/fugui/codes/code-shield/services/semantic_chunker.go) 与 [engine_debate.go](file:///home/fugui/codes/code-shield/services/engine_debate.go) 中实施两项工程参数优化：

1. **降低单分片最大文件数**：
   * 将 `ChunkConfig.MaxFiles` 默认值从 **20 降为 8~10**。
   * **原因**：大模型在处理 20 个 C++ 源码及对应头文件时，极易发生注意力衰减（Lost in the Middle），导致后半部分文件漏检。拆细分片可显著提高各文件的检出稳定性。
2. **废除单分片候选数硬截断**：
   * 移除 `hunterOut.Candidates = hunterOut.Candidates[:maxCap]`（原写死 20 条）；
   * 改用类似 Challenger/Judge 已实现的 **Batching（分批切拆，每批 5 条）** 辩论，确保所有有效候选缺陷均能接受法官仲裁，彻底消除后排文件缺陷被随机丢弃的现象。
