## 〇、一页纸摘要（TL;DR）

**核心矛盾**：
* **现实痛点**：上游扫描依赖大模型（LLM），在同一代码 commit 未发生任何修改时，AI 报出的行号有 **68% 漂移**、分类有 **82% 差异**、标题措辞有 **100% 随机性**。
* **架构困境**：为了抗击上述抖动，系统在 07 号重构中把脏数据直接推给对账层，迫使对账层演化为一个集“倒排别名索引 + 10 维连续浮点加权打分 + 4 道门禁 + 2^N 状压 DP（Bitmask DP）全局指派 + 残差 AI 仲裁”于一体的高维数学黑盒。调用链路深达 6 层，排错极为困难，运维认知门槛极高。
* **反思定性**：增加类似 `EXPLAIN` 的诊断工具只是“给过度复杂的黑盒开窗”，本质上是用偶发复杂度（Accidental Complexity）去治偶发复杂度。真正的破局必须是**从架构第一性原理出发做减法**。

**破局方案：源头物理定桩（Anchoring at Source）+ 离散槽位匹配（Physical Slot Matching）**：
1. **哲学转变（关注点分离）**：**“不在对账阶段包容模糊，而在进入对账前将 AI 观测强行物理离散化”**。物理磁盘上的代码是客观静止的，不管 AI 行号如何飘、措辞如何变，其攻击的代码目标在 AST/语法树上是唯一的物理实体。
2. **前置物理定桩器（Ingestion Stabilizer）**：在 Finding 入库前，通过真实源文件物理语法提取，将飘忽的 AI 输出强行钉在四元组坐标上：
   $$\text{Physical Coordinate} = (\text{FilePath}, \text{ScopeSymbol}, \text{DefectClassMajor}, \text{TargetEntity})$$
3. **极简槽位对账引擎（Slot Matching）**：
   * **彻底删除 10 维浮点数打分**：四元组等值比对，非黑即白；
   * **彻底删除状压 DP（Bitmask DP）**：同函数内的不同缺陷（如 `ptrA` 与 `ptrB`）天然归属不同槽位，复杂度从 $O(2^N)$ 直降为 $O(1)$ 哈希查找；
   * **彻底删除外部残差 AI 仲裁**：对账过程 100% 纯内存本地计算、无网络 IO、毫秒级幂等重放。

### 1.2 偶发复杂度（Accidental Complexity）的演化陷阱

为了解决上述抖动，系统在过去的架构演化中陷入了“打补丁滚雪球”的死循环：

```text
【当前模式：污染下泄，末端治理】

    │

    │
```

**核心痛点定性**：
1. **职责倒置**：对账系统本该是纯粹的“账本出纳（Ledger Accountant）”，却被迫承担了“语义清洗器（Semantic Sanitizer）”的沉重包袱；
2. **黑盒化与不可解释性**：当一个问题未被认领时，排查人员面对的是 10 个权重的浮点累加、门禁分支与状压 DP 转移方程，无法一眼看清因果；
3. **脆弱性传递**：任何一个特征微调（如将权重 0.14 改为 0.12）都会引发全系统全局指派结果的“蝴蝶效应”震荡。

## 二、架构减法核心理念：源头定桩，下游纯粹对账

### 2.1 物理第一性原理（The Physical Ground Truth）

无论大模型生成的文本多么飘忽、行号如何漂移，**被扫描的代码文件在物理磁盘上是绝对客观、静止的 AST 语法树结构**！

* **真实情况**：AI 在同一个函数里报出的“空指针”，无论标在第 42 行（`ptr = getDevice()`）还是第 45 行（`ptr->doAction()`），其在物理源码中操作的**核心变量名称就是 `ptr`**，其所在的**物理函数作用域就是 `GetEnumCfgItem`**，其缺陷本质就是受控的**空指针类型 `NPD`**。
* **架构解耦原则**：
  * **上游定桩（Stabilize at Ingestion）**：在 Finding 离开 AI 引擎、进入台账前的瞬间，由确定性的物理语法解析器将其钉在物理代码桩上；
  * **下游极简对账（Pure Slot Matching）**：对账层只接收干净、离散的物理坐标，回归最朴素的哈希表查找与离散等值匹配。

## 三、机制一：前置物理定桩器（Physical Ingestion Stabilizer）

物理定桩器作为独立的前置管道（在 `PersistScanFacts` 之前运行），负责将不可靠的自由文本转化为离散确定的物理量。

### 3.1 规则 1：缺陷主类严格字典归约（Controlled Taxonomy Bucket）
彻底废弃 LLM 的自由字符串分类，系统定义 16 个核心受控主类枚举（`DefectClassMajor`）：

```go
const (
    ClassNPD        = "NPD"        // 空指针解引用 / 未判空
    ClassMemLeak    = "MEM_LEAK"   // 内存泄漏
    ClassResLeak    = "RES_LEAK"   // 文件句柄/资源泄漏
    ClassUAF        = "UAF"        // 释放后使用 (Use-After-Free)
    ClassDoubleFree = "DBL_FREE"   // 重复释放
    ClassOOB        = "OOB"        // 数组越界 / 缓冲区溢出
    ClassDataRace   = "DATA_RACE"  // 并发数据竞争
    ClassDeadlock   = "DEADLOCK"   // 死锁风险
    ClassIntOver    = "INT_OVER"   // 整数溢出
    ClassUninit     = "UNINIT"     // 未初始化变量使用
    ClassSecInject  = "SEC_INJECT" // 命令/SQL注入
    ClassLogicRisk  = "LOGIC_RISK" // 严重逻辑缺陷
    // ... 扩展受控主类
)
```
任何 AI 产出的原始分类与标题，通过内置的关键词/规则树强制归约到上述字典中。**此举在源头彻底消灭 82% 的分类抖动。**

### 3.2 规则 2：函数符号绝对规范化（Canonical Scope Symbol）
AI 生成的作用域经常在 `ns::cls::func`、`cls::func` 与 `func` 之间反复横跳。
* 定桩器通过语法分析器将符号剥离至：**纯叶子函数名 + 参数个数**（例如 `GetEnumCfgItem#3`）。
* 无论前面是否携带动态命名空间，归一化后的 `ScopeSymbol` 保持恒定。**此举在源头消灭 36% 的作用域前缀抖动。**

### 3.3 规则 3：局部语法窗口物理目标抽取（Target Entity Anchoring）
这是**消灭 68% 行号漂移**的核心杀手锏：

* **算法逻辑**：
  1. 获取 AI 报告的基准行号 $L$；
  2. 在源码物理文件（已在本地工作区克隆）中取 $[L-5, L+5]$ 的局部代码窗口；
  3. 针对归约后的缺陷主类，提取窗口内**被施加危险操作的物理实体名称（`TargetEntity`）**：
     * 若为 `NPD`（空指针）：提取解引用操作符（`->` 或 `.`）左侧的变量名，或赋值返回值的指针名；
     * 若为 `MEM_LEAK` / `RES_LEAK`：提取调用 `malloc / new / open / socket` 接收句柄的变量名；
     * 若为 `OOB`（越界）：提取下标访问 `[]` 中的数组名；
  4. 如果窗口内仅有一个被操作目标，该目标变量名即为 `TargetEntity`。

```text
示例：即使两次扫描行号不同，物理目标唯一确定
源码片段:
42:   DeviceItem* item = GetDeviceItem(devId);  <-- AI 轮次 1 报在此行
43:   if (status != SUCCESS) { ... }
44:   
45:   item->UpdateStatus();                     <-- AI 轮次 2 报在此行

物理定桩提取结果:
  ScopeSymbol:  "GetDeviceItem#1"
  DefectClass:  "NPD"
  TargetEntity: "item"  <── 两次提取结果 100% 完全一致！
```

## 四、机制二：离散槽位匹配引擎（Physical Slot Matching Engine）

在完成物理定桩后，每个缺陷的身份由离散四元组构成：
$$\text{SlotKey} = \text{Hash}(\text{NormPath} \mid \text{ScopeSymbol} \mid \text{DefectClassMajor} \mid \text{TargetEntity})$$

### 4.1 $O(1)$ 槽位直连匹配（取代 10 维打分）

```go
// Matching 输入不再需要浮点打分，直接基于 SlotKey 查表
func MatchObservationToDefects(obs Observation, activeDefects []models.Defect) MatchVerdict {
    // 1. 完全物理槽位命中 (Tier 1: Physical Slot Match)
    slotKey := obs.SlotKey()
    for _, defect := range activeDefects {
        if defect.SlotKey() == slotKey {
            return MatchVerdict{Verdict: "EXISTED", DefectID: defect.ID, Tier: "SLOT_EXACT"}
        }
    }

    // 2. 作用域内弱实体后备命中 (Tier 2: Scope Variable Fallback)
    // 仅在 AI 未能提取出具名变量时，在同函数、同分类下按行号就近贪心匹配
    if obs.TargetEntity == "" {
        nearest := findNearestScopeDefect(obs, activeDefects)
        if nearest != nil {
            return MatchVerdict{Verdict: "EXISTED", DefectID: nearest.ID, Tier: "SCOPE_NEAREST"}
        }
    }

    // 3. 全历史无匹配
    return MatchVerdict{Verdict: "NEW", Tier: "UNCLAIMED"}
}
```

### 4.2 为什么彻底不需要状压 DP（Bitmask DP）？

* **曾经的痛点**：同一个函数内存在两个独立的空指针缺陷（例如第 15 行的 `item` 未判空，第 80 行的 `buffer` 未判空）。在旧架构模糊打分时，系统无法确定谁该配对谁，只能引入状压 DP 搜索全局最优。
* **物理槽位天然隔离**：
  * 缺陷 1：`SlotKey = Hash("main.cpp", "init#0", "NPD", "item")`
  * 缺陷 2：`SlotKey = Hash("main.cpp", "init#0", "NPD", "buffer")`
* **结论**：因为物理变量名不同，它们在数据结构上**天然就落入完全不同的槽位中**！两两之间没有任何重叠或竞争关系，根本不需要任何指派矩阵或状压 DP！

**唯一性约束升级（PostgreSQL 原生部分唯一索引）**：  
结合生产环境 PostgreSQL 的部分唯一索引（Partial Unique Index）特性，仅对活跃（`status = 'ACTIVE'`）的缺陷槽位强制唯一约束，既彻底消除了同函数、同变量活跃缺陷的并发争抢与重复认领，又为历史已归档/已修复缺陷保留了完备的留痕与弹性开单空间：

```sql
-- models/db.go: 生产环境创建活跃物理槽位部分唯一索引
CREATE UNIQUE INDEX IF NOT EXISTS uq_defect_active_slot
ON defects (repo_id, task_type_id, norm_path, scope_symbol, defect_class_major, target_entity)
WHERE status = 'ACTIVE';
```

在持久化流水线提交阶段，借助 PostgreSQL 原生 `ON CONFLICT (id) DO UPDATE ...` 语义，实现单条 SQL 极速幂等状态推进与审计更新。

### 7.2 核心验收口径（不可违背红线）

1. **同 Commit 零增量验收（零假 NEW）**：
   * 针对任意真实代码仓，在代码零变更前提下连续触发 3 轮完整扫描；
   * 第 2 轮与第 3 轮扫描的 `NEW` 缺陷数必须**绝对为 0**，所有有效问题必须 100% 认领存量；
2. **现网 22 组疑难用例 100% 认领**：
   * 以脱敏复盘报告中的 22 组真实抖动样本作为回归基线；
   * 物理定桩 + 槽位匹配对 22 组样本的认领成功率必须达到 **22/22 (100%)**；
3. **同函数独立缺陷互不踩踏**：
   * 同一函数内存在 2 个针对不同指针变量的空指针缺陷，验证两轮扫描后系统稳定维持 2 个独立缺陷，绝不发生误合并；
4. **单轮对账性能跃迁**：
   * 单次对账计算耗时从以往的 100ms~1500ms（含可能存在的 AI 仲裁）压缩至 **< 5ms**（纯内存哈希比对），内存占用下降 90% 以上。
